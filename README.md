# Кошелёк · Karman Premium Glass 1.0.6

**Android 8.0+ · Kotlin 2.0.21 · Jetpack Compose · Android SDK 35 · package `com.mamoro.karman`**

Это полное дерево исходников версии 1.0.6 с двумя темами, тремя режимами графики, карточкой «До дохода» и прежними функциями учёта. База данных сохраняет прежнее имя и схему. Цифровая подпись только оригинальным сертификатом `karman-release`, SHA-256 указан в `SIGNING-SETUP.md`.

Релиз собирается в GitHub Actions (`.github/workflows/android.yml`), а не локальным Android Studio. GitHub Actions запускался успешно для прежней версии 1.0.1 (Debug), но **для исходников 1.0.6 ещё не запускался**. Сборка APK и работа на реальном Android не подтверждены. 

- `docs/UNTIL-INCOME.md` — формула и правила «До дохода».
- `docs/PREMIUM-GLASS.md` — темы, визуальный стиль, оптимизация.
- `SIGNING-SETUP.md` — инструкция для постоянной безопасной подписи; приватные ключи в исходники **не включены**.
- `WORK-DEPLOY.md` — процесс загрузки в GitHub через Work и проверки релизного APK.

## Сборка

В GitHub Actions при push и PR собирается Debug с `testDebugUnitTest`, `lintDebug`, `assembleDebug`. На `main` и при ручном запуске workflow дополнительно требует приватную подпись, а если секреты отсутствуют — сообщает ошибку вместо создания ложного успешного релиза.

**Сохранение данных:** до переустановки и особенно при смене Debug → Release выполните экспорт резервной JSON-копии. При смене подписи Android не сможет установить новое приложение поверх старого с тем же package ID.


## Что нового в 1.0.4

Карточка «До дохода» рисует сложные полупрозрачные фоновые формы средствами Compose Canvas, а не изображением с цифрами. В режиме MAX эффекты переливаются; BALANCED содержит один более медленный блик; FAST показывает тот же стиль статично. Операции, размеры сумм и база данных не изменены. Плавающая кнопка на главной скрыта, поскольку быстрые действия уже доступны ниже карточки.

Чтобы собрать подписанное обновление, загрузите файлы 1.0.4 с сохранением путей в репозиторий FreeWallet; `versionCode = 7`, `applicationId = com.mamoro.karman`. GitHub Actions использует существующие секреты ANDROID_* и сверяет исходный сертификат. ПРИВАТНЫЙ КЛЮЧ НЕЛЬЗЯ включать в исходники.

## Обновление 1.0.4 — исправление вылета на вкладке «Счета»
Первая облигация и первый денежный счёт могут иметь одинаковый числовой ID — теперь Compose использует разные пространства ключей. Обновление не удаляет существующие облигации и не меняет схему базы.
Счета можно переименовывать. Валюта и начальный остаток редактируются, только если счёт не использовался в операциях, планах, шаблонах или инвестициях. Удаляются только несвязанные счета, если остаётся хотя бы один счёт. Для связанных счетов доступно исключение из общего баланса. Курсы управляются исключительно из «Ещё», новые операции берут курс на момент проведения; прошлые суммы не пересчитываются.


## Автоматический учёт покупок (1.0.4)

Вкладка **Ещё** содержит включаемый вручную импорт уведомлений Т-Банка. Для запуска требуется явно разрешить «Карману» доступ к уведомлениям через экран Android и выбрать рублёвый счёт. Импортируются **только расходы**, названия продавцов и суммы покупки. Остальные начисления и реквизиты не используются. Подробности: `docs/BANK-NOTIFICATIONS-1.0.4.md`.


## Версия 1.0.5: банки и субсчета

В разделе «Счета» несколько счетов можно объединить в **одну карточку банка**. В редакторе существующего счета укажите название банка (например, `Т-Банк` или `БеларусьБанк`) и при необходимости последние четыре цифры карты. После этого выберите **«+ Добавить карту / субсчёт»** в карточке банка. У каждого субсчёта собственные операции, начальная сумма и остаток, общий итог банка — сумма дочерних счетов в одной валюте. Банк — только группировка, отдельного счёта с дублирующей суммой не создаётся. Если один банк содержит несколько валют, карточки отображаются отдельно по каждой валюте.

Для автоматического импорта из Т-Банка каждая карта должна иметь уникальные четыре последние цифры: операции из push-уведомлений связываются только с точно определённым рублёвым счётом. Если банк имеет несколько счетов, а номер карты в уведомлении отсутствует или скрыт, автоматическое списание пропускается; пользователю нужно внести покупку самостоятельно. Кешбэк не записывается.

При обновлении 1.0.4 → 1.0.5 выполняется аддитивная миграция базы 1 → 2, сохраняющая идентификаторы существующих счетов, историю операций, инвестиции и настройки. Перед обновлением рекомендуется создать резервную копию через раздел «Ещё». Не удалять установленное приложение, устанавливать только подписанный Release APK.

## Версия 1.0.6: аналитика во вкладке «История»

Внутри «Истории» доступны две внутренние вкладки **Операции** и **Аналитика**, с общими фильтрами месяца и счетов. Аналитика включает график, рейтинги и сравнение расходов с прошлым периодом. Обычные переводы, сделки с ценными бумагами и данные о начислениях из уведомлений не входят в потребительские траты. При недостатке исторических данных средний показатель не рассчитывается. Подробности и правила в `docs/HISTORY-ANALYTICS-1.0.6.md`.

Новая версия **пока не прошла Android Actions/установку на устройстве**. Сборка только с сохранением исходного подписывающего сертификата.
